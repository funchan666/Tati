# 关注状态一致性

所有关注入口必须按用户 ID 读取根节点注入的同一个 `VisitorStore`，使用 `FollowControl`；禁止用页面 `@State`、用户对象副本或进入页面时的快照保存关注状态。

- 关注与取消关注通过 `setFollowing(_:for:)` 写入；使用明确目标状态，重复操作不会反向切换。
- 持久化成功后才发布账户变化；写入失败不得先显示关注成功。
- 关注列表、人数、筛选与邀请列表使用 `followingIDs` / `followerIDs`，互关使用 `mutualIDs`，排除本人和被隐藏的用户。
- 直播间、语音房、个人详情、短视频列表及播放页、聊天页、关系列表与房间成员入口共享同一按钮状态。
- 单向关注不创建粉丝、好友或互关；消息发送和视频通话继续检查双方真实关注关系。
- 切换 Tab、导航、弹层与重启不重置关注记录。拉黑移除关系；解除拉黑不自动重新关注。

当前为同一设备内账户状态同步，未接入跨设备关系服务。此轮仅检查源码、引用和差异，未编译、未运行测试或设备验证。

## 个人资料导航

个人资料使用 NavigationStack 的页面跳转，不在半屏弹窗内展示。房间成员/邀请与视频评论弹窗通过 `profileSheetAction` 交接目标用户，等弹窗 `onDismiss` 后由原页面的 `ProfilePageHandoff` 跳转。头像、名字和正常页面里的资料入口继续直接导航。资料页不提供送礼入口，只保留一组同步关注与聊天操作；直播间、语音房的送礼功能保留。
