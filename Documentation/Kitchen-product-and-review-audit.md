# Tati 厨房功能、资源与审核风险记录

2026-10-22。本轮扫描当前 Tati 的全部 27 份 Swift 源文件、工程配置、资源引用、预置内容与权限入口。仅针对当前项目；没有拿其他应用或 Apple 内部数据作相似度比较。协议网页内容依用户要求不作处理，链接保持原样。

## 已完成的产品改动

新增“厨房手记”，入口位于个人页和烹饪问答页。界面沿用原生 SwiftUI，使用 Image 2 技能的 Host-Native 工作流制作页面参考、食材手记主视觉及两幅食谱册图片，原图与提示词保存在 `ProjectMaterials/KitchenNotebook/`。运行时的文字、按钮、表单、列表仍为原生控件，不用整张设计图代替交互。

- 两道免费食谱：番茄罗勒吐司、柠檬鹰嘴豆碗。
- 份量可在 1–12 人之间调整，食材数量跟随换算。锅具大小、加热时间另作提示，不把数量换算当成安全烹饪时间公式。
- 采购清单按食谱分组，支持勾选、移除；重复添加同一食谱会更新数量，不累加出重复项。
- 试做记录保存本次味道、用餐人数和下次想改的地方，支持草稿及删除，只供本人查看。
- “周日早午餐”“市场晚餐”各含两道食谱，每册 120 金币，当前资料一次解锁，无随机结果、抽奖或新增签到机制。
- 金币确认、余额扣减、解锁和支出记录复用既有原子保存流程；再次确认时重新检查资料所有者、余额和解锁状态。没有改动 Apple 商品 ID、价格档、交易归属、验证及恢复逻辑。
- 钱包与欢迎金币说明已更新，明确食谱册价格和权益范围；免费食谱、清单、笔记、安全工具不收金币。删除资料会移除其解锁记录，页面有相应说明。

界面目录内的文案补齐六种语言；新食谱正文保留英语原文，不把界面语言切换描述成内容自动翻译。

新界面采用容器宽度、原有 NavigationStack、滚动布局和安全区；份量控件用 ViewThatFits 重排，大字保持纵向流动，不按屏幕型号重建数据或视图身份。未做 Duo 真机姿态或折叠遮挡验证。

## 字体与资源

两套本地字体为 DM Sans 与 Fraunces，保留 Google Fonts 来源及 SIL OFL。应用仅打包 DM Sans Regular、SemiBold 与 Fraunces SemiBold 三个静态字重，合计 186,516 字节。UIAppFonts、字体内部名称与目标资源成员已核对；界面使用相对文字样式加载，没有远程字体请求。中文、日文等由平台字形回退，实际混排仍需设备检查。

对压缩开始时的图片和视频资源，源文件合计由 **179.68 MiB 减至 157.19 MiB**，减少约 **22.49 MiB**。这是同批资源的压缩比较，不是 IPA 或 App Store 下载大小。PNG 保持像素不变；JPEG 使用受控质量；视频保留分辨率、音轨和时长并重编码、前移播放索引。只有结果更小时才替换。新增手记素材和字体、移出待确认内容之后，当前应用资源目录约 **151.10 MiB**，精确值见机器记录。

65 份用户提供的原始内容输入哈希未变。三个待确认视频和海报位于应用目标之外；当前只打包 7 条动态视频与 6 条房间视频。人物头像、视频、海报及图片文件名已按成员或食物场景命名，导入清单、脚本及工程同步更新。原始素材和生成参考图不进入应用资源目标。

## 命名与兼容

围绕成员、食物短片、房间对话和厨房记录调整类型及源文件，例如 `MemberKitchenState`、`FoodFilm`、`RoomConversationCue`、`PantryChecklistLine`、`CookingTrialNote`。视频字段使用 `dishCaption`、`recordedMovieFile`、`packagedMovieName`、`posterAssetName`、`publicationReviewState`，奖励余额使用 `rewardCoins`。29 个预置展示名加入自然的简称、姓名缩写或少量美食昵称，保留各自不同的简介。

旧 JSON 键通过 CodingKeys 兼容，持久化文件位置、用户及内容标识、已关注/拉黑/点赞/评论的关联与交易记录保留。旧媒体文件名有显式映射。安全待确认内容也会从旧的编辑内容引用中排除。没有为了改名清空存档、重建购买归属或填充无用代码。

命名改善用于表达业务与维护代码，**不把符号改名、资源改名或压缩当作消除 4.3 风险的证据**。普通系统框架、常见类型和合理的 width/height 参数并不需要刻意改成难懂名称。

## 权限行为

| 操作 | 当前行为 |
| --- | --- |
| 资料拍照 | 主动点击后检查状态；首次拒绝安静结束。之后再次点击且已拒绝，才说明可选择相册或自行打开设置；受系统限制时不提供无效的授权催促。 |
| 摄像头画面 | 只在主动启用时请求；首次拒绝不追加弹窗，视频页结束操作。不会在回到前台时自动申请或重试。后续主动点击且被锁定，才给出中性的可取消设置入口。 |
| 房间语音转文字 | 麦克风首次拒绝后停止，不再继续申请语音识别；语音识别首次拒绝也停止。后续主动点击已锁定的功能，才说明仍可输入文字，并可自行打开设置。 |
| 尚不可用的语音通话 | 移除无实际用途的麦克风权限检查，不为不可用功能收集权限。视频画面也不额外申请麦克风。 |
| 照片与视频选择 | 保留 PhotosPicker 的逐项选择，不申请整个照片库权限，也不追加设置引导。移除不需要的 NSPhotoLibraryUsageDescription。 |
| 通知 | 首次系统拒绝后不追加提示；设置入口仍需用户主动操作。 |

设置只在明确的按钮回调中打开，没有自动跳转。摄像头、麦克风、语音识别三项用途说明保留六语言，语音识别可能交给 Apple 处理的事实不作隐藏。上述行为根据代码分支核对，未执行真实权限弹窗验证。

Apple 依据：[隐私设计](https://developer.apple.com/design/human-interface-guidelines/privacy)、[用途说明](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-purpose-strings/)、[系统照片选择器](https://developer.apple.com/documentation/PhotoKit/selecting-photos-and-videos-in-ios)。首次拒绝后安静结束属于本次用户明确要求的实现约束。
